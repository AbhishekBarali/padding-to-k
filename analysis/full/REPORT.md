## What could not be implemented exactly as written

1. **The matcher was frozen with the registered plan.** Section 5.2 says the matcher is frozen and tagged `scorer-v1` before study outputs are scored. It was frozen with the registered plan instead (tag `prereg-v2.1`, `analysis/matcher.py` v0) and scores the study unchanged. Its accuracy is measured against the 400 entries both authors labelled independently (5.3 b; `analysis/human/RESULTS.md`).
2. **`missed_gold` and `beyond_excerpt` are not decided by the matcher v0.** Those entries land in `in_text_wrong_type` or `plausible_invented`. The matcher-label sheet's strata for these two labels are empty, so, as section 5.3 b says for a label with fewer than 80 entries, their places go in equal parts to the other three labels (134, 133, 133). The labellers can still give either label; `beyond_excerpt` needs the wider source, which the sheet does not include.
3. **Scoring check (5.3 a) done during the full run rather than before it.** The sheet is drawn from the pilot runs as 5.3 a says (65 replies: 40 random, 3 cut at the token limit, 22 unreadable). No scorer bug was found (`analysis/human/RESULTS.md`).
4. **Contrast 5's per-output measure.** "Substantive extra entries per padded slot" is computed per output as excess / (k - n), the slots the grammar forces beyond the true items, so the paired difference is per document.
5. **Contrast 5's Poisson mixed model is a variational-Bayes fit** (statsmodels `PoissonBayesMixedGLM`, random intercept per document, log(k - n) as a covariate), because no maximum-likelihood Poisson mixed model is available in the Python stack used here. It is reported next to the primary bootstrap test only, as a rate ratio with a posterior interval.
6. **Mixed models report the intercept.** Covariates are centred and factors sum-coded so the intercept is the average paired difference; that intercept and its Wald interval are what the table shows.
7. **"Says it is short" outside the list.** The note rules of `harness/common.py` are applied, unchanged, to each sentence of the text outside the JSON (split at . ! ?, new lines and colons). Notes those rules do not cover ("there is only one request") are not caught, so the says-short share is a lower bound.
8. **n = 0 apart.** Section 6.1 says n = 0 is analysed apart from n = 1 to 3; the primary contrasts pool every n < k cell (as the pilot's stop rules did) and table 1a gives n = 0 and n >= 1 separately.
9. **Same-weights pairs: "10 points".** The main measure is now in entries, while the 10-point rule was written for over-count; the pair table gives both and judges the rule on over-count points.
10. **Overlay.** `analysis/gold_overlay.jsonl` does not exist yet, so the overlay variant equals the frozen lists. The code reads one row per corrected item and treats it as an added true item (`op: remove` subtracts one).
11. **Human-check frame.** The 400-entry frame is every substantive entry of the full runs (8 GPU models and the hosted models, `none` included). The thinking-pair runs are not in it: they are still running, and the draw has to be fixed before labelling starts.
12. **Not computed here**: RQ5, RQ7 and RQ8 need the teacher-forced and hidden-state passes, which were not run on the full-study outputs; the robustness arms ran only in the pilot.
